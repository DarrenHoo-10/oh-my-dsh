# Agent Note: 对话选区操作与上下文侧边聊天

Status: implemented

[English](2026-08-15-transcript-selection-and-side-chat.md) | 中文

## Problem

桌面对话视图缺少把选中的记录文字以评论形式加入下一条提示词的路径，也没有保留来源历史的上下文聊天区域和位于底部面板的命令终端。会话导出还会把 HTTP URL 交给 `file://` 渲染器；桌面 carrier 没有 TCP 服务，因此浏览器 fetch 会失败。

## Decision

Chat 视图拥有根据浏览器 Range 定位的选区工具栏。添加片段时会立即记录只存在于运行时输入区的 annotation，其中包含稳定的消息行偏移和引用；带编号的标记可打开可选评论编辑器，也支持删除。对话记录容器改变大小时，标记会重新测量该 Range，因此右栏布局变化后序号仍跟随原文片段。原文范围会显示带编号的蓝色标记，输入状态机则把所有待发送 annotation 序列化到下一条进入日志的普通消息中，但绝不隐式发送。模型会收到完整封装，而对话记录渲染器会把它投影为普通问题和一个紧凑的注释数量附件；展开附件可以查看引用与评论。上下文侧边聊天会创建来源 Session 的 Host 临时 fork，保留继承历史作为模型上下文，并只向对应子会话发送后续提问和图片附件。fork 响应会暴露权威种子长度；客户端会把子会话保留在临时注册表中，通过 `SessionListState.byId` 和自身 Session scope 提供给右栏，但不会放入 `ids`。Host 同样会从列表／搜索基线和全局 Session 列表帧中排除 `sidechat` Session，但仍会把其 Agent 状态发送给被寻址的子 Session。侧聊 Chat 渲染器会隐藏种子 seq 之前的节点，并渲染第一条子会话用户消息及其后的所有节点。所选片段会作为一条普通待发送注释进入子会话输入状态机，因此首次成功发送会消费它，后续草稿不会继续显示固定引用。已完成的侧聊回答可以作为一条待发送注释加入来源 Session 输入区；该操作会转移完整回答，但不会提交来源输入区，并会用稳定的子会话／消息标识替换此前尚未发送的副本，避免重复添加。可调整宽度的右栏拥有多个子会话标签页。其 store 投影会保留普通输入区状态，但在浏览器加载与保存时删除临时子会话 id，因为 renderer 重启后无法恢复持有这些子会话的 Host 进程。子会话不存在于进程内注册表时，对应标签也会自行移除。每个有效标签会显式打开未处于主舞台的子会话历史窗口，而不会修改应用的当前会话；窗口就绪前显示加载状态，只在加载成功后通过子会话作用域挂载标准 Chat 渲染器和完整输入区，加载失败时则显示错误且不提供发送控件。Markdown、工具调用、图片、注释、权限控件及模型选择均保留主栏行为。模型选择、运行状态、取消操作及其他输入控件分别操作对应子会话；停止侧边聊天不会取消来源 Session，停止来源 Session 也不会取消侧边聊天。在运行中的普通输入区按 Escape 只会调用该输入区的取消回调；文字输入法组合、按键重复、空闲 Session 及 one-shot subagent 会保留原有输入行为。修改来源会话不会重新绑定已打开的侧边聊天。Host 会保留临时 fork 的消费方 handle、跳过 Workspace 附加，持久化则忽略其 `sidechat` origin。关闭单个标签时会先等待 handle 完成释放，再移除界面状态和子会话 scope；关闭整个面板会对所有标签执行同样操作，任一销毁失败时面板保持打开。释放会停止子 Agent 并移除实时 Session，因此以后打开时会创建全新的 fork，已关闭侧聊在重启后也无法恢复。分隔线允许右栏使用视口可用宽度，不设任意的最大值，同时保留可用的最小宽度和中央栏让步规则。

侧聊 Chat 渲染器会把每条新的可见用户节点设置为 transcript 顶部内边距处的语义滚动锚点。Thinking 和回复增长会保留该位置，而不是追随底部；回答完成也不会释放锚点。用户滚动或主动回到底部会释放锚点，并恢复普通追底权。可切换的底部区域会在当前会话目录下启动一个持续运行的 shell。浅色终端只拥有一条可编辑的 PowerShell 提示行；Electron Main 拥有子进程，移除名称类似凭据的环境变量，通过受信任的 preload bridge 转发输出和 shell 的实际当前目录，并在关闭面板或应用时等待终端退出。每条提交命令后都会发送当前目录消息，因此 `cd` 等 shell 状态会更新渲染器，无需在渲染器中推导路径。渲染器不会获得 Node API。主输入区和侧边输入区都会渲染会话统计栏；投影存在数据时，其中包含轮次、耗时、缓存命中率及 token 总数。对话正文使用 Windows 原生界面字体栈，代码与终端输出使用等宽字体。会话导出通过现有桌面 Host bridge 执行 HEAD 和 GET，再把 ZIP 字节交给 Electron 保存对话框，而不是让 `file://` 页面访问 `http://dsh.internal`。“打开位置”继续通过 `ctx.workspaces.openPath` 和 Host 提供方执行。

## Alternatives considered

**创建只存在于渲染器本地的侧边对话。** 这种回答无法由实时 Agent、子 Session 日志、分支和模型历史重建。Host 临时 Session 可以在打开期间保留事件溯源行为，同时不让它进入持久化。

**把引用直接追加到 textarea。** 普通草稿文字无法保留来源范围、编号标记和独立评论，也无法明确移除其中一个片段。

**让工具详情与上下文聊天共用一个右侧面板。** 模式切换会让一个阅读任务遮住另一个，也无法在底部面板提供终端。

**向渲染器暴露 Node 进程和文件系统 API。** 这会削弱上下文隔离，并让浏览器组件依赖 Electron。窄化的终端和文件保存 IPC 会把进程及文件所有权保留在 Main。

**立即使用伪终端。** PTY 能改善全屏程序和控制序列行为，但会增加原生依赖及打包面。首个实现使用适合普通命令的持续标准输入 shell，并明确记录该限制。

## Consequences

选区评论复用输入状态机，并通过普通用户消息日志变得可重建，但序列化文本不会作为对话正文暴露。侧边聊天选区与其他输入区注释共享相同的发送、清空和失败恢复周期。侧边聊天历史在打开期间以子 Session 为权威，不会改动来源对话记录；继承节点只在展示层隐藏，该 Session 及其标签标识不会进入持久化，并会在释放时销毁。面板只有在子会话历史窗口可渲染后才提供发送功能。可调整宽度的右栏与底部区域拥有彼此独立的几何状态。终端可以在绑定的工作区内运行普通 PowerShell 命令，但在加入 PTY 提供方之前不支持全屏终端程序。桌面导出改用原生保存路径，不再依赖不存在的本地 HTTP 监听器。
