# Agent Note: Transcript selection actions and contextual side chat

Status: implemented

English | [中文](2026-08-15-transcript-selection-and-side-chat.zh.md)

## Problem

The desktop conversation view had no comment-oriented path from selected transcript text to the next prompt, no contextual chat region that retained the source history, and no command terminal in the bottom panel. Session export also handed an HTTP URL to a `file://` renderer, where the browser fetch failed because no TCP server exists in the desktop carrier.

## Decision

The Chat view owns a selection toolbar positioned from the browser Range. Adding an excerpt immediately records a runtime-only composer annotation containing its stable row offsets and quote; its numbered mark opens an optional comment editor and supports deletion. The mark remeasures that Range when the transcript container resizes, so right-column layout changes keep the number attached to its excerpt. The source range receives a numbered blue highlight, and the input machine serializes every pending annotation into the next ordinary logged message without sending implicitly. The model receives that complete envelope, while the transcript renderer projects it as the ordinary question plus a compact annotation-count attachment whose disclosure contains the excerpts and comments. Contextual side chat creates a Host-owned temporary fork of the source Session, retains inherited history as model context, and sends subsequent prompts and image attachments only to that child. The fork response exposes the authoritative seed length; the client retains the child in a temporary registry that makes it available through `SessionListState.byId` and its Session scope while omitting it from `ids`. The Host likewise excludes `sidechat` Sessions from list/search baselines and global Session-list frames, but still streams their Agent status to the addressed child Session. The side Chat renderer hides nodes before the seed seq while rendering the first child user message and every later node. The selected excerpt enters the child input machine as one ordinary pending annotation, so the first successful submission consumes it and later drafts do not retain fixed quote chrome. A finalized side-chat answer can be attached to the source Session's composer as one pending annotation; the action transfers the complete answer without submitting the source composer, and a stable child/message identity replaces an earlier pending copy instead of duplicating it. The resizable right column owns multiple child tabs. Their store projection retains ordinary composer state but removes temporary child ids during both browser hydration and storage, because a renderer restart cannot recover the Host process that owned those children. A tab also removes itself when its child is absent from the process-local registry. Each valid tab explicitly opens that off-stage Session's history window without changing the application's current Session, shows loading state until the window is ready, and mounts the standard Chat renderer and complete composer only after that load succeeds; a load failure renders an error and no send controls. Markdown, Tools, images, annotations, permission controls, and model selection retain their main-column behavior. Model selection, running state, cancellation, and every other composer control therefore address the child independently; stopping side chat never cancels the source Session, and stopping the source never cancels side chat. Escape in a running ordinary composer invokes that composer's cancellation callback only; IME composition, repeated Escape events, idle Sessions, and one-shot subagents retain their existing input behavior. Changing the source Session does not retarget an open side chat. The Host retains the temporary fork's consumer handle, omits Workspace attachment, and persistence ignores its `sidechat` origin. Closing one tab waits for handle disposal before removing its UI state and child scope; closing the panel does the same for every tab and stays open on failure. Disposal stops the child Agent and removes the live Session, so a later opening creates a fresh fork and closed side chats cannot recover after restart. The divider permits the side column to use available viewport width without an arbitrary maximum while preserving a usable minimum and the center-column concession.

The side Chat renderer makes each new visible user node a semantic scroll anchor at the transcript's top inset. Thinking and response growth preserve that position instead of following the bottom; completion does not release it. Reader scrolling or the explicit back-to-bottom action releases the anchor and restores ordinary follow ownership. The toggled bottom row starts one persistent shell in the current Session directory. Its light terminal owns one editable PowerShell prompt, while Electron Main owns the child process, removes credential-like environment variables, forwards output and the shell's current directory through the trusted preload bridge, and waits for terminal shutdown when the panel or application closes. The current-directory message follows every submitted command, so shell state such as `cd` updates the renderer without deriving paths there. The renderer receives no Node API. The main and side composers both render the session statistics dock, including turn counts, timings, cache hit rate, and token totals when their projections contain data. Conversation prose uses the native Windows UI font stack; code and terminal output use monospaced fonts. Session export performs its HEAD and GET operations through the existing desktop Host bridge and hands the ZIP bytes to an Electron save dialog instead of fetching `http://dsh.internal` from the `file://` page. Opening a filesystem location continues through `ctx.workspaces.openPath` and the Host provider.

## Alternatives considered

**Create a renderer-local side conversation.** It would render responses that the live Agent, child Session log, forks, and model history could not reconstruct. A temporary Host Session preserves event-sourced behavior while it is open without making it durable.

**Append the quote directly to the textarea.** Plain draft text cannot preserve the source range, a numbered mark, or a separate comment, and it makes removing one excerpt ambiguous.

**Keep Tool details and contextual chat in one right panel.** Switching modes would hide one reading task behind the other and leave no terminal surface in the bottom panel.

**Expose Node process and filesystem APIs to the renderer.** That would weaken context isolation and make browser components depend on Electron. Narrow terminal and save-file IPC operations keep process and file ownership in Main.

**Use a pseudo-terminal immediately.** A PTY would improve full-screen and control-sequence behavior, but it adds a native dependency and packaging surface. The first implementation uses a persistent standard-input shell for ordinary commands and states that limitation explicitly.

## Consequences

Selection comments reuse the input machine and become reconstructable through the ordinary logged user message without exposing their serialization as chat prose. A side-chat selection has the same send, clear, and failure-restore lifecycle as any composer annotation. Side-chat history remains authoritative in the child Session while it is open and does not alter the source transcript, but inherited nodes are presentation-hidden, the Session and its tab identity are intentionally absent from persistence, and disposal destroys it. The panel cannot offer submission before its child history window is renderable. The resizable right column and bottom row have independent geometry. The terminal runs ordinary PowerShell commands in the bound workspace, but full-screen terminal applications remain unsupported until a PTY provider is added. Desktop export uses the native save path and no longer depends on a nonexistent local HTTP listener.
